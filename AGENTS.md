# Правила работы с репозиторием

Прежде чем менять код, прочитать `.specify/memory/constitution.md`, `docs/status.md` и спецификацию затронутой функции.

- Писать документацию по-русски, BSL — в стиле платформы 1С.
- Сохранять объем ВКР: настройка штатного расписания всех подразделений плюс HTTP-обмен. Не сводить проект к одному API.
- Различать сведения пользователя, подтвержденные метаданные и предложения разработчика.
- Для новых функций сначала создавать `spec.md`, `plan.md`, `tasks.md`. Для исправлений синхронизировать существующую спецификацию.
- Не считать источники BSL установленным расширением, статическую проверку — запуском в 1С, тестовую базу — рабочей.
- Не менять основную конфигурацию и существующие базы без конкретной задачи. Код продукта размещать в расширении.
- Не добавлять SQL-доступ, отдельный Python/Node.js backend или базу расписания без изменения архитектурного решения.
- Не загружать в Git информационные базы, полную конфигурацию вуза, персональные данные, пароли, токены и настройки подключения.
- Не перезаписывать исправленные пользователем Word-файлы из старых генераторов.
- Перед завершением выполнить подходящие проверки и обновить `docs/status.md`. Невыполненные платформенные проверки указать явно.
