# Исходники 1С

`CommonModules/CSAPIRequestValidation/Ext/Module.bsl` — первый чистый модуль проверки дат и UUID. XML рядом описывает один общий модуль; **это не полный экспорт конфигурации/расширения и не готовый CFE**.

## Проверка в отдельной тестовой среде

1. Создать/выбрать отдельную тестовую конфигурацию, совместимую с 8.3.27.2342. Не использовать рабочую базу.
2. Создать неглобальный общий модуль `CSAPIRequestValidation`. Свойства: Сервер=Да, Внешнее соединение=Да, Вызов сервера=Нет, Привилегированный=Нет, Повторное использование=Не использовать. Скопировать исходник из `src/CommonModules/.../Ext/Module.bsl`.
3. Создать аналогичный тестовый модуль `CSAPIRequestValidationTests`, скопировать `tests/1c/CSAPIRequestValidationTests.bsl`. Тестовый модуль не переносится в рабочую поставку.
4. Проверить синтаксис, обновить только свою отдельную тестовую конфигурацию. Вызвать `CSAPIRequestValidationTests.ВыполнитьВсе()` из доступной тестовой обработки или внешнего соединения.
5. Сохранить возвращенную структуру, версию платформы и дату в локальный протокол. При ошибке исправить код/спецификацию и повторить сценарии. Не менять статус задачи на выполненную без запуска.
6. После этого проверить включение в расширение целевой базы. Сама установка расширения и HTTP-публикация еще не реализованы.

Вход функции — `Соответствие`, не объект HTTP-запроса. Преобразование HTTP-параметров, повторяющиеся ключи, поиск объектов, права, запросы данных и публикация появятся в следующих спецификациях.

## Передача на проверку пользователю

Выбранный порядок: вы выполняете компиляцию и запуск в своей тестовой базе. Можно использовать уже доступную тестовую обработку с произвольным кодом; отдельную универсальную консоль в этот проект не добавляем.

Вызов на сервере или через внешнее соединение:

```bsl
Результат = CSAPIRequestValidationTests.ВыполнитьВсе();
```

Ожидаемый успешный результат: структура `Успех = Истина`, `КоличествоСценариев = 33`. При первой ошибке тестовый модуль вызывает исключение с названием проверки. 11.11.2026 пользователь получил успешный результат всех 33 сценариев через тестовое расширение; см. [протокол](../docs/verification/platform-validation.md). Для разбора достаточно текста ошибки, имени модуля и строки; реальные сведения студентов и учетные данные не нужны.
