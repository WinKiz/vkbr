# Диагностика схемы расписания через существующий HTTP-сервис

Только для своей тестовой базы и локальной публикации. Код читает метаданные, а не записи расписания. Новые общие модули и новый маршрут для этого шага не требуются.

1. В Конфигураторе открыть расширение Denis, HTTP-сервис TestService и его модуль.
2. Скопировать текущий модуль в локальный файл вне Git, чтобы восстановить после проверки. Не использовать старую выгрузку как резервную копию текущего кода.
3. Заменить весь текст модуля содержимым ScheduleSchemaHelloGET.bsl из этой папки. В нем одна функция HelloGET и две служебные подпрограммы.
4. Проверить синтаксис, сохранить и применить изменения именно тестового расширения.
5. Открыть прежний локальный адрес публикации с окончанием /hs/test/hello. Не менять Apache, URL-шаблон и обработчик HelloGET.
6. Ожидается JSON: status=ok, mode=schema_only, register=Расписание, fields — список имен и типов полей. Число полей заранее не задано. Передать этот JSON для подготовки запроса чтения. При ошибке передать текст, модуль и строку; HTTP 500 не считать пустым расписанием.
7. После завершения диагностики восстановить сохраненный модуль и применить изменения. Этот шаг не является рабочим API и не возвращает занятия.

Дополнительно нужны название проекта и подтверждение, что 4МО — точное наименование группы (буквы кириллицей/латиницей важны). Известные даты: проект 01.09–31.12.2026, размещенные занятия 02.09–11.12.2026.

## Отдельный сервис в расширении Denis_s

Для целевой базы используется отдельный маршрут. Корневой URL `schedulecheck`, шаблон `/schema`, метод `GET`, обработчик `HelloGET` из того же BSL-файла. После применения расширения проверьте `<адрес веб-публикации>/hs/schedulecheck/schema`. Точный адрес и доступ к сервису в публикации рабочей базы подтверждает администратор. Если Apache возвращает 404 и на базовом адресе публикации, сначала уточните адрес.
