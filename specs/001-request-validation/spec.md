# 001 — проверка параметров запроса расписания

Статус: исходники подготовлены, платформенная проверка и интеграция ожидаются. Версия контракта 0.1, 11.11.2026.

## Цель и граница
Проверить параметры до обращения к учебным данным. Модуль не читает регистры, не ищет объекты по UUID, не проверяет права и публикацию и не формирует HTTP-ответ самостоятельно. Адаптер 004 переводит результат отказа в HTTP 400. Неверная конфигурация лимита является ошибкой сервера, а не клиента.

## Контракт
Вход — `Соответствие` строковых имен и значений. Обязательны `dateStart`, `dateEnd` строго в ASCII-формате YYYY-MM-DD; пробелы не обрезаются. Даты должны существовать; начало не позже конца. Результат — либо нормализованные параметры, либо первая понятная ошибка; исходные значения секретов/объектов в сообщение не подставляются.

Внутренний интервал: от 00:00 dateStart включительно до 00:00 следующего за dateEnd дня исключительно. Это календарные значения 1С, не UTC; часовой пояс применяется только в адаптере согласно Q03. Если верхнюю границу представить невозможно, вернуть отказ, не обрезать период.

Необязательные `group`, `teacher`, `auditory` принимают UUID из 36 символов с дефисами 8-4-4-4-12 и ASCII hex. Регистр букв не важен, результат — каноническая строка. Отсутствующий ключ дает Неопределено; явно переданный пустой фильтр — ошибка. Валидный UUID еще не доказывает существование объекта, это отдельный этап с HTTP 404. Нулевой UUID синтаксически допустим и также требует поиска объекта.

`МаксимумДней` — необязательное положительное целое число, задаваемое вызывающим кодом. Неопределено означает отсутствие проверки лимита в этом чистом модуле. Рабочий адаптер обязан получить согласованный лимит до публикации; произвольное значение здесь не вводится. Продолжительность считается включительно.

Неизвестные ключи отклоняются для обнаружения опечаток. Повторяющиеся параметры HTTP должны выявляться до построения Соответствия: здесь исходная кратность ключей уже недоступна. Это проектные решения ADR-007 для сверки с кампусом.

## Критерии приемки
- **AC01:** 2026-09-01…2026-09-07 дает [01.09 00:00, 08.09 00:00).
- **AC02:** одинаковые даты дают один полный календарный день; пересечение месяца и года корректно.
- **AC03:** 2028-02-29 допустимо; 2026-02-29, 2026-02-30, 2026-13-01 отклоняются.
- **AC04:** отсутствие, нестроковый тип, пустота, пробелы, иная длина/разделители, Unicode-цифры и обратный период отклоняются.
- **AC05:** каждый из трех фильтров и их комбинация сохраняются; UUID нормализуются; неверный и пустой UUID отклоняются.
- **AC06:** лимит 7 допускает семь дней и отклоняет восемь; неправильная настройка лимита вызывает исключение сервера.
- **AC07:** модуль не зависит от объектов Университета и не изменяет входную коллекцию или базу.
- **AC08:** функция и сценарии компилируются и выполняются в платформе 8.3.27.2342; интеграция проверяется отдельно в целевой конфигурации.

## Ошибки
`INVALID_PARAMETERS_TYPE`, `UNKNOWN_PARAMETER`, `DATE_START_INVALID`, `DATE_END_INVALID`, `PERIOD_REVERSED`, `DATE_END_BOUNDARY`, `PERIOD_LIMIT_EXCEEDED`, `FILTER_INVALID`. Эти коды — предложение контракта, а не готовая реализация HTTP.
