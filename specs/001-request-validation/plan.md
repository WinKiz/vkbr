# Технический план 001

1. Чистый серверный общий модуль `CSAPIRequestValidation`; общий, глобальный, привилегированный и повторно используемые результаты выключены. Внешнее соединение разрешить для тестового вызова, серверный вызов с клиента не нужен.
2. Экспортировать `ПроверитьПараметрыЗапроса(Параметры, МаксимумДней)` и возвращать структуру Успех/КодОшибки/Сообщение/Параметры.
3. Проверять ASCII-формат дат, создавать Дата(год,месяц,день) с обработкой исключения; формировать исключительную границу прибавлением суток с проверкой представимости.
4. Проверять UUID до создания платформенного объекта; нормализовать строковое представление. Не разрешать ссылочные типы предметной базы в этом слое.
5. Подготовить тестовый общий модуль `CSAPIRequestValidationTests` с экспортной функцией `ВыполнитьВсе()` и независимыми сценариями контракта. Он не входит в рабочую поставку.
6. До платформенной проверки исходники лежат как BSL и XML общего модуля, а не выдаются за полный экспорт расширения/CFE.
7. После компиляции и прогона в отдельной базе проверить загрузку в расширение Университета и добавить отчет с версией платформы, датой, числом сценариев и результатом.

Внешние библиотеки и база данных не нужны. Проверка репозитория на Python контролирует комплектность артефактов и JSON-примеры, но не доказывает поведение BSL.
