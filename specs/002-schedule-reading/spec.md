# 002 — чтение фактического расписания

Дата: 25.11.2026. Статус: обследование текущих метаданных; запрос к учебным данным и приемка не выполнены.

## Цель
Прочитать сохраненные фактические занятия из штатной подсистемы и сверить их с Мастером расписания. Первый контрольный пример — группа 4МО. Это проверка одного примера в общем объеме всех подразделений 2026/2027, а не сокращение объема ВКР.

## Подтверждено пользователем
- Фактическое расписание 4МО составлено пользователем в режиме предприятия.
- Границы проекта: 01.09.2026–31.12.2026. Занятия размещены 02.09.2026–11.12.2026.
- Содержимое регистра, полнота и сохранность занятий через HTTP еще не проверены.

## Этапы и контракт
1. Диагностика метаданных: временный GET существующего тестового маршрута /hs/test/hello возвращает только имена и типы измерений, ресурсов и реквизитов регистра Расписание. Не читает занятия, контингент, учетные данные или строку подключения. Отсутствующий регистр — явный диагностический отказ с HTTP 500, а не пустое расписание.
2. После получения схемы и точного проекта подготовить запрос чтения. Источник — готовые размещения, не исходная нагрузка ДанныеДляРасписания. Использование СрезПоследних, фильтров фактического типа и связей подтвердить по текущему модулю штатного чтения, не угадывать.
3. Локальный тестовый вызов ограничить группой, проектом и периодом. Пользовательские значения передавать параметрами запроса 1С. Название группы служит для выбора, после подтверждения использовать ссылку/UUID; неоднозначность не скрывать.
4. Сверить занятия и всех участников с Мастером. Сначала неделя с занятиями, затем весь период; отсутствие занятий 01.09 и после 11.12 само по себе не ошибка.
5. Продуктовый API и разрешение публикации — зависимые этапы 003/004. Фактический тип не означает разрешение внешней публикации. Данный шаг не открывает выдачу учебных данных внешним потребителям.

## Критерии приемки
- AC01: диагностический обработчик возвращает schema_only и поля фактического регистра без чтения записей; JSON UTF-8, отсутствующий регистр явно отличим от пустой выборки.
- AC02: проект, группа, фактический тип, время и связи установлены по текущим метаданным/штатному коду; не смешиваются проекты и версии записей.
- AC03: даты трактуются включительно; отбор периода сохраняет все пересекающие его занятия по подтвержденной модели времени.
- AC04: сохранены группы/подгруппы, преподаватели и аудитории поточных занятий; нет молчаливого усечения и недоказанного устойчивого ID.
- AC05: число и состав занятий контрольной недели и всего периода совпадают с Мастером; расхождения разобраны, результат записан.
- AC06: чтение не меняет базу; персональный состав студентов, секреты и выгрузка данных не включаются в Git.

## Открытые вопросы
Точное название/ссылка проекта; точное написание и UUID группы; текущие поля регистра и перечисления типов; штатный запрос чтения; сохранение фактических размещений; права HTTP-пользователя. Q01–Q08 сохраняются. Решения по устойчивому ID и внешней публикации не считаются принятыми на основании одного локального теста.
