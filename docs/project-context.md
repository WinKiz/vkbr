# Контекст и границы проекта

## Подтверждено пользователем
- Цель — полностью настроить штатную подсистему расписания и обмен с кампусом БГПУ.
- Охват — все имеющиеся подразделения; первый учебный год 2026/2027. Перечень подразделений устанавливается обследованием, не произвольным сокращением объема.
- Платформа 8.3.27.2342, «Университет ПРОФ» 2.3.2.28. Есть тестовая база и Конфигуратор.
- Структура, корпуса, аудитории, преподаватели, группы и планы частично заполнены. Полнота, корректность, контингент, нагрузка и поручения еще проверяются.
- Сейчас используется старый самописный «Редактор расписания», работающий вручную и копированием шаблонов.
- Исходные сведения подтверждают учебная часть, ректорат, АСУиИБ. Структура: https://bgpu.ru/sveden/struct.
- Сроки и неподтвержденные реквизиты можно отмечать «уточнить».

## Выводы по локальной выгрузке от 13.10.2026
- `РегистрСведений.Расписание` — готовые размещения; в штатном модуле используется `СрезПоследних` с условиями перекрытия времени.
- `ДанныеДляРасписания` — исходные задания; связь с расписанием — проект и UUID строки расчета. Это не универсальный физический ключ обоих регистров.
- Преподаватель — `Справочник.Сотрудники`. Аудитория — `Справочник.СтруктураУниверситета` с соответствующим видом.
- Справочник структуры сам не иерархический; подчиненность хранится отдельным регистром. Группа и подгруппа связаны в контексте контингента.
- Исходный UUID строки расписания является реквизитом. Его уникальность и устойчивый ID API нужно проверить на данных.
- Статический снимок не подтверждает совпадение с текущей базой, полноту данных и активность расширений.

## Принятый объем API из ТЗ
GET `/schedule`, `/directories/groups`, `/directories/teachers`, `/directories/auditories`; JSON UTF-8; оболочка расписания `status`, `data`, `meta`; даты включительно; фильтры по стабильным ID, совместно — И; только разрешенные данные. Пустой результат существующего объекта — HTTP 200, а ошибки не маскируются пустым массивом.

## Проектные решения, которые еще проверяются
Собственный HTTP-сервис и дополнительные сведения о разрешении публикации в расширении. Basic поверх HTTPS — исходное предложение, не подтвержденная окончательная настройка. curl и Git — инструменты разработки; отдельный backend не нужен.

## Незакрытые вопросы
| Код | Вопрос | Что от него зависит |
|---|---|---|
| Q01 | Режим совместимости, вариант базы, активные расширения и права | Состав и загрузка расширения |
| Q02 | Кто и как разрешает публикацию, какой признак/версия используются | Выдача реальных данных; по умолчанию запрет |
| Q03 | Границы семестров, часовой пояс, проект и тип выдачи | Преобразование дат и выборка |
| Q04 | Адрес сервиса, потребитель кампуса и согласование JSON | Интеграционная приемка |
| Q05 | Максимальный период и допустимый объем ответа | Рабочая конфигурация сервиса; скрытого усечения нет |
| Q06 | Уникальность UUID и реальные пары участников | Устойчивые ID и сборка занятий |
| Q07 | Состав и качество справочников, нагрузка, поручения | Полное расписание всех подразделений |
| Q08 | Способ аутентификации и инфраструктура HTTPS | Внешняя публикация |

Не все вопросы блокируют первый независимый модуль. Они блокируют зависимые функции, а не заполнение документации и разработку чистой проверки параметров.
