# Журнал решений

| ID | Решение | Основание | Статус |
|---|---|---|---|
| ADR-001 | Данные и бизнес-логика расписания остаются в 1С | ТЗ и имеющаяся база | Принято в проекте |
| ADR-002 | Доработка поставляется расширением | Обоснование технологий; совместимость еще проверяется | Принято с проверкой Q01 |
| ADR-003 | Собственный HTTP-сервис вместо прямого объектного API OData | Нужны сборка занятий, стабильный контракт и проверка публикации | Принято; ТЗ не запрещает OData |
| ADR-004 | Соблюдать цикл spec → plan → tasks → code → evidence | Начало работы по SDD 11.11.2026 | Принято; Spec Kit CLI не установлен |
| ADR-005 | Первый шаг — независимая проверка дат и UUID-фильтров | Не требует чтения реальных учебных данных | Реализуется в 001 |
| ADR-006 | Не выбирать веб-сервер, СУБД, лимиты и публикацию произвольно | Не хватает сведений о среде | Ожидает обследования |
| ADR-007 | Строгий синтаксис дат и канонические UUID; пустой явно переданный фильтр — ошибка | Предложение для однозначного контракта | Проектный контракт 001, сверить с кампусом |
