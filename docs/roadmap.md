# План разработки

1. **000 — обследование тестовой базы.** Сверить версию/режим/расширения, структуру и готовность данных. Результат: протокол, перечень исправлений и соответствие объектам. Полная конфигурация в Git не загружается.
2. **001 — проверка параметров API.** Строгие даты, включительная верхняя граница, UUID-фильтры и конфигурационный лимит. Первые BSL-модули без доступа к данным.
3. **002 — чтение и нормализация расписания.** Запросы 1С, срезы, реальные связи, устойчивые ID, проверка всех участников; сначала контрольные данные и спецификация.
4. **003 — разрешение публикации.** Модель состояния, ответственный, версия, снятие разрешения при изменении; согласовать Q02.
5. **004 — HTTP-адаптер.** Методы, маршруты, JSON, коды ошибок, учет платформенных отказов и контракт с кампусом; никакой выдачи при незавершенном 003.
6. **005 — справочники и приемка обмена.** Фильтрация по реальным видам и составам, журнал, проверки доступа и отказов.
7. **006 — рабочее расписание и внедрение.** Исправление структуры/справочников, контингент/нагрузка/поручения, Мастер, проверка коллизий, приемка всех подразделений и документация.

Обследование и настройка идут параллельно по времени с разработкой API, но не считаются завершенными из-за наличия кода. Номера функций — порядок освоения кода, а не отмена зависимости от подготовки данных.
